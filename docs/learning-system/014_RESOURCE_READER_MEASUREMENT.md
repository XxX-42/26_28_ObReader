## Actual production path

`viewer-adapter/vocabulary/controller.js:handleTap` resolves a physical text token, displays a pending pill and posts `vocab-token-tap`. `plugin/main.js` validates the request, captures document/openRequest/renderer identity, obtains its production singleton Dictionary and awaits `initializeVocabulary()`. Only then does it run personal `getTerm` and dictionary `lookup` concurrently. It rereads personal state after dictionary completion, applies personal translation/phonetic/status priority, then posts `vocab-entry-result`. The Viewer checks documentId/openRequest/requestId/key/page before `updatePillRecord` and layout. `preparing` progress messages and the initial pending pill are not final dictionary completion. This initialization wait, second personal read, bridge scheduling, token resolution and DOM paint are absent from injected service benchmarks.

Host startup queues a zero-delay warmup timer near the end of onload. That callback constructs the Dictionary (including Dexie/schema constructor dependency), starts manifest verification and Worker prewarm via `checkAvailability` without awaiting Worker readiness. Neither the timer nor asynchronous Worker work is free merely because onload returns first. Successful v3 query avoids a full Dexie generation import; constructor cost still belongs in the measured window. No deterministic query bug was found in this audit.

## Paired startup experiment

Use a separate test-only build/profile that controls only `scheduleVocabularyDictionaryWarmup` activation. Both arms load the same bundle, settings, Reader fixture and resources with vocabulary enabled; the baseline suppresses only availability activation, never the entire plugin. No lookup occurs during startup. Do not modify production main/bridge to prepare this experiment here. A future fixture may apply the toggle before plugin load under test ownership, recording its exact implementation/hash and restoring it after each process. If such control is not available, the paired attribution gate remains blocked rather than substituting plugin-disabled startup.

Start Native tracing before bundle evaluation (startup tracing/process launch, not post-start CDP attach). Use a predeclared common window from bundle start through a fixed elapsed endpoint long enough for all deferred availability/Worker-ready work in every arm, plus a quiet margin. Incomplete work invalidates the pair; retain the failed pair and rerun both arms with a longer common window. Record onload-return, timer-dispatch, manifest verification, Worker-ready, Reader-interactive and window-end marks separately. Cold means a new PID after prior owned PID exits; OS file cache policy stays explicit and identical.

Extract non-overlapping renderer-main top-level tasks in that interval, preserving stack/category provenance. Report aggregate main-thread CPU including tasks shorter than 50 ms, longest task, TBT, elapsed startup milestones and Worker CPU separately. Async I/O elapsed is not main-thread blocking; TBT alone loses all sub-50ms work. Use at least 20 counterbalanced A/B pairs, publish every signed enabled-minus-baseline renderer-main CPU increment and nearest-rank p50/p95 (do not clamp negatives), and predeclare p95 <50 ms as the aggregate acceptance criterion. Include bootstrap cost common to both arms; separately identify resource-attributed slices where trace stacks support it. If the trace cannot attribute main tasks or isolate the activation toggle, report **NOT_MEASURED**.

Pure extraction support is available in `tests/resource-startup-pair-support.mjs`: `summarizeStartupPair(baseline, enabled)` validates cold/pre-bundle/deferred-work and package/fixture/window identity, clips and sums top-level tasks, and preserves signed increments. It intentionally returns **NOT_VERIFIED** for one pair and cannot invent Native provenance. Input times are milliseconds on each run's monotonic trace timeline. The tests demonstrate why zero TBT cannot close this gate, reject nested double counting and incomplete/attach-only evidence, and preserve negative increments.

Validation command: `node --test tests/resource-startup-pair-support.test.mjs tests/dictionary-host-state.test.mjs`. These are deterministic Node checks, not Native timing acceptance.
