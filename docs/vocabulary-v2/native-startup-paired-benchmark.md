# Native paired plugin startup measurement (prepared, NOT_RUN)

This collector extends the attach-only pattern of `tests/native-dictionary-resource-v3-benchmark.mjs` and uses `native-config.mjs` exact Vault/config-directory guards. It does not launch Obsidian, deploy packages/resources, toggle plugins, open Readers, call domain initialization directly, or bypass isolated initialization. Root controls all package staging, backup/restore and actual plugin-manager enable/disable actions. Only an actual instrumented package's normal onload is measured.

Prepare two **owned built packages** outside any Vault, retaining their unmodified originals and existing manifest/styles/assets. Run `node tests/native-startup-paired-benchmark.mjs --prepare /outside/v2-original/main.js /outside/v2-probe/main.js`, then equivalently for v3. Output parents must exist. Exactly one readable `async onload() {` seam is required; unsupported/minified packages fail rather than guessing. The generated file transparently delegates normal onload through a wrapper and carries source/output SHA-256 provenance in a separate JSON file. Root must verify installed bytes against that instrumented SHA before each run; the collector's packageSha256 is a coordinator assertion, not a readback of installed bytes. No Node filesystem reads Vault resources.

Use five predeclared pairs, order `v2,v3; v3,v2; v2,v3; v3,v2; v2,v3`, same Native process and exact test Vault, zero Readers. These are **plugin-cold instance** measurements with retained process/origin, OS caches and any persistent databases; never fresh-process or fresh-origin cold. Disable the plugin before arming each phase. Root must wait for prior unload/background work to quiesce and restore equivalent resource/config state between variants. Any outstanding work invalidates attribution; retain the failure rather than retrying selectively. Resource/schema switches remain root's explicit deployment responsibility.

After Native lease release, set normal native-config variables (`OBSIDIAN_VAULT_PATH=/Users/jiajia/Documents/ObReader-Apple-Test`, `OBSIDIAN_ACTIVE_VAULT=1`, `PDF_READER_CDP_URL=http://127.0.0.1:49786`, and the correct `OBSIDIAN_CONFIG_DIR`) plus `OBREADER_NATIVE_STARTUP_LEASE=exclusive-after-native-gates`. Example phase:

```sh
node tests/native-startup-paired-benchmark.mjs --observe v2-baseline 1 INSTRUMENTED_PACKAGE_SHA256 /outside/evidence/pair1-v2.json
```

Collector prints ARMED; only then root enables the already-staged package through the normal authorized plugin manager. It waits up to 120 seconds for that package's real onload. Root disables it afterward, restores the other owned package through the approved deployment workflow, then repeats the corresponding candidate phase. The collector never toggles. Failed observations retain partial metrics; evidence files are created exclusively. Do not run on a locked Mac or overlap Native/UI/other benchmark leases. After all observations, root restores original package and prior enabled state using its backup workflow; source injection exists only in the explicitly staged test package.

`node tests/native-startup-paired-benchmark.mjs --summarize /outside/evidence/summary.json /outside/evidence/pair*.json` requires exactly one successful baseline/candidate per pair and distinct instrumented package SHA values. Missing, duplicate or failed pairs remain NOT_MEASURED. It does not manufacture retries or omit failures.

Metrics and the <50ms boundary:

- `record.syncInvocationMs`: wall time of the actual onload invocation through its first async suspension/return. The wrapper's bookkeeping is excluded where possible and identical across variants. Five candidate-minus-baseline deltas each <50ms satisfies **only the synchronous onload invocation** criterion. This is main-thread synchronous occupancy elapsed time, not a CPU counter; scheduling/GC can affect it.
- `record.asyncSettledWallMs`: actual onload promise settlement wall duration, including asynchronous work, I/O waits, and synchronous continuations. Never label this blocking or CPU.
- `manifests`: actual DataAdapter.read calls ending in `/manifest.json`, with method invocation time and async elapsed time kept separate. Only that method is temporarily wrapped, preserving receiver/arguments and failures; finally restores the original own descriptor/inherited lookup. JSON parse/validation after the adapter resolves is outside these timings. Other manifest filenames/readBinary or filesystem initialization paths are not covered.
- `longTasks`: capability-probed renderer PerformanceObserver longtask entries during the armed window. Filter their timestamps against onload start/settlement for exploratory correlation. They cover all renderer activity, omit tasks below 50ms, and may be unavailable in this Electron version; absence is not zero blocking. Longtask duration is not exclusive plugin CPU. The observer is disconnected finally.
- `mainThreadCPU` and `fullStartupAddedBlocking` remain **NOT_MEASURED**. This collector does not yet have a Native-verified CPU/tracing capability. To decide the broad <50ms *added startup blocking* target, root must capture validated renderer task/CPU trace across matched baseline/candidate startup windows, attribute synchronous continuation/manifest parse/verification segments after each await, and separate other plugin/UI activity. Until that exists, a passing invocation-only delta cannot satisfy the full startup gate.

The wrapper delegates to normal onload exactly once and returns its value/rejection; it cannot replace domain initialization. Runtime observer state uses a uniquely owned Symbol, refuses existing ownership, and is restored/deleted finally. A cleanup conflict fails rather than overwriting another actor. Instrumented packages require separate root restore after measurement. No trace, UI, CDP or actual benchmark was executed during preparation. Validation: two pure support tests and syntax check only.
