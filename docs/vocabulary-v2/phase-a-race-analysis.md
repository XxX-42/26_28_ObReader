# Phase A gate runner and concurrency evidence

## Gate layout

`scripts/test-vocabulary-gates.mjs` keeps the existing `tests/*.test.mjs` suite intact and checks a static, exhaustive `fast` / `browser` classification before starting. A new test file without a classification, a removed file left in the list, or a duplicate classification stops the runner before tests run.

The gates are:

- `fast`: every non-real-browser test file, with a process cap of four (`--jobs 1..4`). Browser launcher and cleanup helper tests are here because they use fake child processes and do not launch Chromium.
- `browser`: all real-browser regression suites, one test process and browser at a time. A TAP skip is a gate failure, including the existing “Chrome or Edge is required” skip. Existing test timeouts stay in force; the runner adds no timeout.
- The browser gate also runs `tests/offline-smoke.mjs` as a direct Node script after the `.test.mjs` suites; this supplements, rather than weakens, the exhaustive test-file classification.
- `race`: `autosave-mobile-regression.test.mjs` and `highlight-multiline-regression.test.mjs` launch together in each round. The default is ten rounds and fewer than ten is rejected. There is no retry: every round records both child statuses, and any failed or skipped child keeps the aggregate red even if later rounds pass.
- `all`: runs `fast`, then `browser`, then `race`, preserving each child result in one JSON report.

Example commands:

```sh
node scripts/test-vocabulary-gates.mjs fast
node scripts/test-vocabulary-gates.mjs fast --jobs 2
node scripts/test-vocabulary-gates.mjs browser
node scripts/test-vocabulary-gates.mjs race --rounds 10
node scripts/test-vocabulary-gates.mjs all --rounds 10
npm run test:fast
npm run test:browser
npm run test:race -- --rounds 10
npm run test:gates -- --rounds 10
```

Each invocation writes a JSON report and raw stdout/stderr files beneath the ignored `tests/artifacts/vocabulary-gates/runs/` directory. Child records keep exit code, signal, spawn error, detected skips, raw log paths, and byte counts. `--report` accepts a different path only under that ignored directory. Each child receives a unique temporary directory for Puppeteer profiles and a unique runner artifact directory. Current browser tests bind local servers to port `0`, so the operating system assigns each server its own port.

The JSON report fingerprints source state before and after the requested gates using SHA-256 over Git-tracked files plus untracked source files (`.mjs`, `.cjs`, `.js`, `.css`, `.html`, `.json`, and TypeScript variants). It excludes `docs/`, `dist/`, `node_modules/`, test-vault data, `.git`, and artifact directories. A changed or unavailable final fingerprint sets `acceptanceEligible` to false, even if all tests exit zero, so an in-flight source edit cannot be mistaken for a frozen-source pass.

`tests/test-artifact-root.mjs` routes `VOCABULARY_GATE_ARTIFACTS_DIR` into the eight original failure-diagnostic suites: annotation interaction, autosave mobile, FreeText undo, multiline highlight, iPad pointer policy, mouse input, sidecar FreeText geometry, and sync bridge. Their evidence and browser launch records now land inside their own child directories. Other browser suites still use their existing ignored artifact locations; those files are run sequentially in the browser gate. The port marker documents the gate allocation while test servers continue to request port `0` directly. `browser-test-launch.mjs` already creates a unique Crashpad directory per launch, and Puppeteer creates a separate temporary browser profile for each child process. The runner leaves the browser launch and cleanup helpers unchanged.

The mobile autosave fixture now holds its sidecar identity response until after it verifies the viewer is read-only, the Square tool is disabled, no synthetic annotations exist, and no save has started. It then releases identity, waits for read-only to clear, and only then calls the test's synthetic `annotationStorage.setValue`. The first-save deadline remains the existing eight seconds. Logs record the identity request, host confirmation, observed readiness, first dirty mutation, and first save; a first-save timeout prints this timeline and bridge state. This guards the fixture precondition and makes future failures diagnosable without changing production autosave scheduling.

## Historical concurrency evidence

The original full-suite run artifacts are under `/private/tmp/obreader-vocab-state-semantics/tests/artifacts`. The relevant launch records identify autosave mobile as owner PID 13611 / Chrome PID 13634, launched at 17:28:34Z and ending at 17:29:15Z with browser exit code 2 and `cleanup-failed`. The matching highlight evidence file, `highlight-multiline-regression-1792258133564-14353.json`, reached `validation-complete`: it contains all three candidate and diagnostic interactions, and `candidateFailures` is empty. Its launch record says Chrome PID 14392 was forced at 17:29:37Z and exited with code 2. That highlight report also recorded a console 404 and a PDF.js `HighlightEditor.unselect` page error reading `div`; it does not show those errors caused a validation failure. The test runner's raw stdout/stderr for these two children is absent, so the autosave assertion that failed and the precise teardown cause cannot be recovered from these artifacts alone.

This failure window overlapped other browser tests. Between 17:26Z and 17:31Z, the launch records show 26 Chrome launches and as many as nine simultaneously live Chrome child processes. FreeText undo and iPad browser processes in the same window also ended with nonzero browser exit codes, while other browser processes exited normally. Earlier in the same artifact set, autosave mobile and highlight both overlapped other browser launches and exited naturally with code 0; that earlier window peaked at seven live Chrome child processes. A serial rerun at 17:33Z also passed both target tests. This pattern makes higher browser-process load a credible contributor, but does not identify CPU, memory, file descriptor, or another specific exhausted resource, nor establish one shared autosave/highlight failure mechanism.

Other archived logs must not be merged into that exact run. In a separate `wal-sidecar-v3-1` checkout, an archived concurrent log shows autosave mobile timing out after eight seconds while waiting for its first save; the highlight test there failed its exact-source transform precondition before launching a browser. Those are useful examples of distinct failure signatures, but they are not raw logs for the 774-test artifact run and do not establish that run's root cause. An earlier `EPERM` listener error in the artifact directory also occurred before browser launch and is not evidence for the 17:28 failures.

The pair does not configure `userDataDir`. Puppeteer 25.12.0 creates a unique `puppeteer_dev_chrome_profile-*` directory with `mkdtemp` for each launch. The browser cleanup helper validates the child PID, executable, and temporary profile before signaling a process; it does not remove the profile ahead of child exit. Puppeteer's own `onProcessExit` callback removes its temporary profile after the browser process exits. The target test servers both bind loopback port `0`, so neither a shared profile nor a fixed-port collision is supported by the code reviewed. The new runner further gives each child a distinct `TMPDIR` and artifact directory.

The autosave fixture had a separate readiness weakness: it waited for the host's `opened` message and the annotation editor layer, but `opened` is posted without waiting for the asynchronous page-identity request to finish. The bridge starts read-only and clears that state only after an identity-confirmed snapshot is applied. A synthetic storage mutation in that interval bypasses the disabled editing controls; the autosave scheduler marks work pending but refuses to arm a timer while read-only. Applying the later identity snapshot clears read-only without rearming that synthetic autosave. The new held-response choreography captures this ordering boundary and prevents the fixture from creating that unsupported state. This establishes a concrete test-fixture precondition defect in the prior setup, but does not prove that it caused the historical 17:28 failure because those exact child stdout/stderr streams are unavailable.

The run used local Node 26.3.1, Puppeteer Core 25.12.0, and Chrome 155.0.8059.84. Its report at `tests/artifacts/vocabulary-gates/runs/run-2026-10-17T18-24-04-788Z-36883-fd8f0f2a/report.json` recorded 13 passed, 7 failed, and 0 skipped children: autosave passed all ten, while highlight child exit status was 0 in rounds 1–3 and 1 in rounds 4–10.

All ten autosave children exited 0. In each, the held identity phase had `readOnly=true`, the Square tool disabled, annotation storage size zero, and no saves. Every timestamped sequence was identity request, host confirmation, confirmation observed/read-only cleared, first synthetic dirty edit, then first save; the first save arrived about three seconds after `markDirty`, within the unchanged eight-second assertion. This run validates the corrected test precondition under the two-browser race. It does not demonstrate that the old invalid fixture order caused the original 774-run failure.

The candidate highlight JSON recorded the same page error in all ten rounds: `Cannot read properties of undefined (reading 'div')` from `HighlightEditor.unselect` at `viewer/build/pdf.mjs:13139:36`, during the focused save/reopen check. The legacy-capture diagnostic variant recorded no page errors. The candidate highlight child processes for rounds 1–3 exited 0 because the test's explicit assertion for candidate page errors was added while this race was running; at 02:25:17 CST (18:25:17Z), both that assertion and a bridge `app.close` focus wrapper were written. Rounds 4–10 then exited 1 on the newly added assertion. The same page error appeared after the focus wrapper, so that attempted wrapper did not prevent this observed exception. This report is therefore a mixed-source diagnostic run, not a final stable gate result; its raw JSON and child streams preserve all ten observations. The 19:26 and final 19:45 full-gate runs passed the Highlight Browser case and all ten Highlight Race rounds, so the earlier `unselect` error is not a current failure in either report. The relationship between the old page error and the historical forced Chrome exit code 2 remains unproven because the original child streams are unavailable.

The original concurrent run's precise autosave assertion and teardown cause remain undetermined because its child stdout/stderr is missing. The latest Race failure has a different retained signature: autosave made its first save on time, then Chrome 155 exited during cleanup with a Crashpad dump and the Mac shutdown watchdog diagnostic. Although the later focused stability report used the matched 154.0.8037.57 headless shell, it did not rerun the complete autosave/highlight Race pair against this failure. The ten-round gate preserves both children’s logs and statuses without retrying failures, so the fix must be demonstrated by a new complete run with no failed or skipped children.
