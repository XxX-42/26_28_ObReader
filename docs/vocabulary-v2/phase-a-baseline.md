### Sync bridge assertion mapping

`tests/sync-bridge-regression.test.mjs` keeps the Sidecar operation protocol's business guarantees explicit while the source PDF remains immutable:

| Required behavior | Current regression evidence |
| --- | --- |
| Failed save does not claim persistence. | Inject a host persistence failure before the Sidecar harness transaction; require `save()` to return false, the operation to remain dirty, the confirmed revision not to advance, the request to settle, automatic retry to pause, and no durable write or operation publication. Retry with a current exact-identity ACK and require the same UUID to become clean. |
| Failed recovery preserves retryable edits and reports the error. | Edit the already saved Square under its existing UUID, fail `flush` before Sidecar commit, and require `ok: false`, `dirty: true`, an unconfirmed revision, a settled recovery request, and the injected error. A retry must durably recover the same UUID and edited thickness under an exact ACK. |
| A saved Square survives reopen as the same visible annotation. | Require the durable save and ACK to contain the original UUID and exact PDF-space rectangle; reopen the source and Sidecar snapshot; require that UUID, style, editor type, positive real DOM bounds, and serialized PDF geometry to match the saved operation. |
| Delete, undo/redo, and reopen retain tombstone identity. | Keep the same UUID through delete, undo, redo, and save; reopen original bytes with the Sidecar snapshot; send a live pre-delete snapshot tagged with the immediately previous open request and require the tombstone to remain active. |
| Explicit export retains the PDF.js writer's actual mixed-page output. | Export a separate PDF after creating Square, Ink, and freehand Highlight editors on pages 2 and 10. Check the new page-two and page-ten `/Annots` order against the per-page tool creation order, and keep ordinary Sidecar save/recovery byte-free. |
| Export preserves annotations outside Sidecar tracking. | The page-ten fixture starts with Square+Popup, an untracked Line+Popup, Ink, freehand Highlight (`/Subtype /Ink`, `/IT /InkHighlight`), and Underline. Compare the exported refs in source order and retain each ref's name, contents, rectangle, parent/popup links, subtype, and highlight intent. This directly covers Popup and untracked refs that operation-only assertions cannot observe. |
| The live source remains unchanged. | After edits and explicit export, compare the current Reader PDF bytes to the original SHA-256 and require that only explicit export invoked the binary PDF writer. |

The former successful `sync-apply-prepare` / `sync-apply` flow has no equivalent in this architecture: it merged draft PDF bytes and replaced/reopened the renderer's document in place. Sidecar writes now persist UUID operations only, while the source PDF stays byte-identical; accepting a merged PDF payload would restore the retired binary mutation path. The regression therefore keeps both prepare and apply rejection assertions (`immutable-source-annotations-only`) and checks that the original PDF object, close count, and binary-save count remain unchanged. The replacement business checks are exact UUID operation ACK/retry, stale open/snapshot rejection, tombstone/reopen identity, and a distinct explicit annotated export. A PDF.js ref is asserted only for original source refs in the export; new sidecar operation UUIDs are not given PDF refs during normal save.

## Additional confirmed Vocabulary defect

The scanner correctly joined physical `compa-` / `rable` into logical `comparable`, but the host required `normalize(rawSurface) === key`. A physical hyphen therefore made the authenticated request fail. `logicalSurface` now travels with physical segment/raw text evidence; the host verifies both the logical key and a bounded permitted dehyphenation of the raw text. Ordinary requests retain their previous validation. The pill displays the logical word. Scanner → Controller message → host → pill response tests preserve rejection of arbitrary mismatched keys.

The focused four-suite run passed 119 assertions. This does not replace the full gates.

## Gate policy

Fast runs at most four child processes. Functional Browser runs one browser suite at a time. Race runs the two historical concurrency-sensitive suites together for at least ten rounds, with independent profiles, ports and evidence directories; every failure is retained and no retry erases it. No timeout was increased and no scenario is skipped to obtain acceptance. See `phase-a-race-analysis.md` for the original concurrent artifact limitations and the raw gate reports under the ignored `tests/artifacts/vocabulary-gates/` directory.

The ordinary `npm test` entry point now runs the bounded Fast and Functional Browser gates, retaining the complete test manifest and offline smoke. `npm run test:race` retains a genuinely concurrent gate; sequential Functional results cannot close it. The runner fingerprints source before and after all gates and rejects mixed-source runs. In particular, diagnostic run `run-2026-10-17T18-24-04-788Z-36883-fd8f0f2a` is not acceptance: it retained seven failed child exits, and the page-error assertion was added during that exploration.

The hydration fix changes only a temporary `onceAdded` adapter in the existing bridge: it invokes PDF.js bookkeeping with `focus=false` while restoring an external editor, then restores the exact original method descriptor even on failure. Normal user creation keeps `onceAdded(true)`. An attempted close-focus handoff did not fix the exception and was removed. No PDF.js source or input controller was changed.

No schema v2, Context, Review or History implementation has started. No real Vault, source PDF, Annotation WAL format, PDF.js vendor, main branch or remote branch has been modified by this phase.
